# 命名

项目名确定为 `Stargate`。目标是比 `PassWall` 更现代，同时准确表达“专注、干净、稳定、AI 友好、OpenWrt 代理平台”的方向。

## 命名标准

- 不绑定个人前缀。
- 不直接叫 `anytls-*`，因为长期目标是 sing-box 平台，不只是一个协议导入器。
- 尽量短，容易读，适合作为 GitHub 仓库名、LuCI 应用名、命令名和服务名。
- 避免太像现有项目，减少误解。
- 最好能表达“路径、网关、边界、清晰、控制面”的含义。
- 服务名适合写成小写中划线或单词，例如 `/etc/init.d/projectname`。

## 最终选择

### Stargate

含义：稳定、可控、可观测的网络入口。

优点：

- 名字比 `PassWall` 更有辨识度，也更适合做成独立产品。
- 不绑定某个协议，后续支持 AnyTLS、Vision、DNS、透明代理和前端都自然。
- `stargate` 适合作为仓库名、服务名、配置目录和命令名。
- 语义上更像“网关平台”，适合 AI 配置和可视化控制台。

注意：

- 项目文案不承诺“绝对隐蔽”或“绝对安全”，只描述可验证、可回滚、低耦合的工程目标。
- 如果公开发布，需要确认同名项目和商标风险；技术仓库名可以先使用小写 `stargate`。

## 曾考虑候选

### ClearWall

含义：清晰、干净、低耦合的代理墙。

优点：

- 和 PassWall 有语义继承，用户一眼知道是代理平台。
- `clear` 能表达配置干净、状态可解释、可回滚。
- 仓库名、服务名、命令名都好写：`clearwall`。

缺点：

- 仍然带 `wall`，容易让用户预期它是 PassWall 的完整替代品。
- 名字偏稳，不够锋利。

### FluxGate

含义：流量网关，强调可控的流量入口。

优点：

- 比 ClearWall 更有产品感。
- 能覆盖 AnyTLS、Vision、DNS、透明代理、Web UI 等后续方向。
- `fluxgate` 作为服务名和仓库名都自然。

缺点：

- 不直接说明 OpenWrt 或代理，需要 README 解释。

### RouteForge

含义：构建和锻造路由策略的平台。

优点：

- 适合强调 AI 辅助生成配置、策略可视化、规则编排。
- 后续做前端、诊断、配置生成器时空间很大。

缺点：

- 听起来偏“路由规则平台”，不如 `Wall/Gate` 直观。

### VeilGate

含义：带隐蔽性的网关，适合强调特征安全和代理协议。

优点：

- 名字有辨识度。
- 和 AnyTLS、Reality、Vision 这类协议方向气质相符。

缺点：

- `veil` 有隐藏含义，项目介绍需要更谨慎，避免过度承诺安全性。

### SingPilot

含义：sing-box 的配置驾驶舱。

优点：

- 直接表达核心是 sing-box。
- 很适合 AI 配置、前端管理和诊断工具。

缺点：

- 绑定 sing-box 较强。如果未来支持其他核心，名字会受限。

## 改名影响

- README 标题和描述。
- `/etc/stargate` 配置目录。
- `/etc/init.d/stargate` 服务名。
- `scripts/stargate.sh` 文件名和内部变量。
- LuCI 应用包名。
- GitHub 仓库名。
